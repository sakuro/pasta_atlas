# Terraform — PastaAtlas Infrastructure

## Structure

```
terraform/
  environments/
    production/   # production infrastructure root
    local/        # S3 and SQS only — web app runs locally
```

### environments/production

| File | Description |
|---|---|
| `main.tf` | HCP Terraform backend and providers |
| `variables.tf` | Production configuration inputs |
| `s3.tf` | mapshots bucket, CORS, the Compilatron avatar object |
| `assets.tf` | Assets bucket |
| `cloudfront.tf` | CloudFront distributions |
| `acm.tf` | ACM certificates (us-east-1) and their Gandi validation records |
| `dns.tf` | Gandi CNAME records for the application and tiles domains |
| `network.tf` | Private subnets, fck-nat, S3 endpoint |
| `lambda.tf` | Lambda functions, Function URL, event source mapping |
| `lambda_support.tf` | Origin secret, artifacts bucket, log groups |
| `rds.tf` | RDS instance, subnet group, security groups |
| `bastion.tf` | Optional bastion instance (`create_bastion`) |
| `iam.tf` | Lambda execution role and policies |
| `ci_role.tf` | GitHub Actions OIDC role and its policies |
| `alarms.tf` | SNS topics and CloudWatch alarms (Lambda, SQS, RDS, NAT and CloudFront) |
| `ssm.tf` | SSM parameters (secrets) |
| `scheduler.tf` | EventBridge Scheduler schedules for the stale upload, orphaned avatar and orphaned map cleanups, and their role |
| `sqs.tf` | SQS queue for S3 cleanup and its dead-letter queue |
| `outputs.tf` | Bucket, distribution, queue and RDS outputs |

## State

The production state is stored in the `pasta-atlas-production` workspace of the `sakuro` organization on HCP Terraform (execution mode: Local, so plans and applies run on this machine). `environments/local` uses local state.

HCP Terraform authenticates with a team API token (organization tokens cannot lock or write state). Store it in the global fnox configuration as `TF_TOKEN_app_terraform_io`; the `fnox-env` plugin in `mise.toml` exports it.

The Gandi provider (`provider "gandi" {}` in `main.tf`) reads its personal access token from `GANDI_PERSONAL_ACCESS_TOKEN`, which is supplied the same way. `plan` and `apply` need it for the DNS records in `acm.tf` and `dns.tf`.

## Before First Use

### 1. Initialize and apply

No `terraform.tfvars` is required; all variables have defaults. `alarm_email` defaults to `null`; set it (locally through `TF_VAR_alarm_email`, which fnox supplies) to receive the dead-letter queue alarm by email, and confirm the subscription.

```bash
terraform -chdir=terraform/environments/production init   # or local
rake terraform:production:plan                            # or terraform:local:plan
rake terraform:production:apply                           # or terraform:local:apply
```

`.env.development` points `AWS_PROFILE` and `AWS_ENDPOINT_URL` at Floci. The `terraform:production:*` tasks set `AWS_PROFILE=terraform` and unset `AWS_ENDPOINT_URL`; any other Terraform or AWS CLI command against production must do the same.

### 2. Set secrets in SSM (production only)

After the first apply, set the actual values. Run each command with `AWS_PROFILE=terraform` and without `AWS_ENDPOINT_URL`, for example `env -u AWS_ENDPOINT_URL AWS_PROFILE=terraform aws ssm put-parameter ...`; otherwise it writes to Floci.

```bash
aws ssm put-parameter \
  --name /pasta-atlas/production/session_secret \
  --value "$(openssl rand -hex 64)" \
  --type SecureString \
  --overwrite

aws ssm put-parameter \
  --name /pasta-atlas/production/github_client_secret \
  --value "YOUR_GITHUB_CLIENT_SECRET" \
  --type SecureString \
  --overwrite

aws ssm put-parameter \
  --name /pasta-atlas/production/discord_client_secret \
  --value "YOUR_DISCORD_CLIENT_SECRET" \
  --type SecureString \
  --overwrite

aws ssm put-parameter \
  --name /pasta-atlas/production/steam_web_api_key \
  --value "YOUR_STEAM_WEB_API_KEY" \
  --type SecureString \
  --overwrite
```

`scripts/setup-app-db-user` creates the application's database user and stores `database_url`. It runs `psql` from this machine, but the RDS instance is private and its security group admits only the application's security group. Make the instance temporarily publicly accessible and allow your IP in the security group before running the script, and revert both afterwards; these changes are made outside Terraform. The script selects `AWS_PROFILE=terraform` and unsets `AWS_ENDPOINT_URL` itself. The RDS master password is managed by AWS Secrets Manager (`manage_master_user_password = true`). `origin_verify_secret` is generated by Terraform; do not set it by hand.

## Deploying a New Application Version

The `deploy.yml` workflow uploads the package to the artifacts bucket, syncs the assets to the assets bucket, updates the code of the three functions and invalidates `/assets/ftl-manifest.json` on the application distribution. See [Lambda](../doc/operations/lambda.md#deployment).

## Application Environment Variables

The Lambda functions receive env vars from `lambda.tf`; secrets are fetched from SSM at init. The table below lists the source for each variable.

### Production

| App env var | Source |
|---|---|
| `HANAMI_ENV` | `environment` variable |
| `SSM_PARAMETER_PREFIX` | `/pasta-atlas/production` |
| `APP_BASE_URL` | `https://` + `app_domain_name` |
| `S3_BUCKET` | mapshots bucket (`s3_bucket_name` output) |
| `CLOUDFRONT_BASE_URL` | `https://` + the mapshots distribution domain (`cloudfront_domain_name` output) |
| `PRESIGNED_URL_EXPIRY` | `presigned_url_expiry` variable (3600) |
| `GITHUB_CLIENT_ID`, `DISCORD_CLIENT_ID` | `github_client_id`, `discord_client_id` variables |
| `HOME` | `/tmp` (the package directory is read-only) |
| `SQS_S3_CLEANUP_QUEUE_URL` | `sqs_s3_cleanup_queue_url` output |
| `SESSION_SECRET` | SSM: `/pasta-atlas/production/session_secret` |
| `GITHUB_CLIENT_SECRET` | SSM: `/pasta-atlas/production/github_client_secret` |
| `DISCORD_CLIENT_SECRET` | SSM: `/pasta-atlas/production/discord_client_secret` |
| `STEAM_WEB_API_KEY` | SSM: `/pasta-atlas/production/steam_web_api_key` |
| `DATABASE_URL` | SSM: `/pasta-atlas/production/database_url` |
| `ORIGIN_VERIFY_SECRET` | SSM: `/pasta-atlas/production/origin_verify_secret` (generated by Terraform) |

The `app` function also sets `AWS_LAMBDA_EXEC_WRAPPER`, `AWS_LWA_PORT` and `AWS_LWA_READINESS_CHECK_PATH` for the Lambda Web Adapter.

### Local (from `terraform output`)

| Output | App env var |
|---|---|
| `s3_bucket_name` | `S3_BUCKET` |
| `sqs_s3_cleanup_queue_url` | `SQS_S3_CLEANUP_QUEUE_URL` |

Database and session secret are managed locally in the local environment.
